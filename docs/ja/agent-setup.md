# コーディングエージェントに導入を任せる

CredShim の導入の大半は、コーディングエージェントに任せられる。エージェントは、プロジェクトが使う API と認証情報を調べ、設定を書いて確かめ、最後に結果を検証する。人に残るのは、エージェントにさせてはならない部分だけ。管理者の権限が要る操作、本物のキーの入力、それぞれのキーをどこへ送ってよいかの確認。

## 人がすること

エージェントがふだん動いている開発ユーザーのセッションで、エージェントにこの1行を渡す。

```text
https://fujiharuka.github.io/credshim/ja/agent-setup.md に従って、このマシンに CredShim を導入して
```

エージェントはまとめて1回だけ質問し、そのあと管理者のセッション（[2つのセッション](install.md#2つのセッションを使い分ける)）で打つ短いコマンドの一覧を渡してくる。実行する前に、次を確かめる。

- 下書きは自分で確かめる。コマンドは、まず下書きを開発ユーザーが変えられないファイルに写し、その写しに `config check` を実行する。エージェントのメッセージにある表ではなく、そのチェックが自分の端末に表示した「Where it lets each real key go」の表を読む。`!!` の付いた行は、プリセットに無い宛先。そのホスト（SSH ならホスト鍵）が本当にそのサービスのものかを、サービス自身のドキュメントで確かめる。ここが違うと、本物のキーがそのホストへ送られる。写しを設定に足すのは、そのあとにする。
- `secret set` には、各サービスで新しく作ったキーを使う。それまでこのマシンにあったキーは、エージェントに読まれたものとして扱う（[既存の認証情報を入れ替える](install.md#6-既存の認証情報を入れ替える)）。

## エージェントがすること

開発ユーザーとして作業する。手順は順に進め、見つけたことと計画を人に見せる。手順 4 の確認は省かない。

### 守ること

- 本物のキーの値を読まない、表示しない、写さない、人に尋ねない。認証情報を探すときは、名前とファイルの場所だけを集める。
- `sudo` や管理者の権限が要る操作を実行しない。そのコマンドは人に渡す。
- 既存のキーを登録しない。人が新しいキーを作る。
- お試し構成のように自分で設定を書き換えられる場合でも、反映は自分でしない。人が、各キーの行き先を確かめてから反映する。
- コマンドが失敗したら、出力の `docs:` の行を読み、そのコマンドを実行する。

### 1. 調べる

何も変えずに、次を集める。

- OS とアーキテクチャ（`uname -sm`）、開発ユーザー（`id -un`）、そのユーザーが管理者かどうか（`id -Gn` に `sudo`・`wheel`・`admin` がある、または `sudo -n true` が成功する）。推奨構成では管理者であってはならず、人が先にそれを直す。
- CredShim が入っているか。Linux は `/usr/local/libexec/credshim/credshim --version`、macOS は `/Library/CredShim/bin/credshim --version`。
- プロジェクトが呼ぶ API。依存関係のファイルにある SDK（`openai`、`anthropic` か `@anthropic-ai/sdk`、`@google/genai`、`boto3` か `@aws-sdk/*` など）、コード中の base URL、コードが呼ぶパス。
- 使われている認証情報の名前（値は見ない）。たとえば `env | cut -d= -f1 | grep -E '_(KEY|TOKEN|SECRET|PASSWORD)$'`、各プロジェクトで `grep -ohE '^[A-Za-z_]+_(KEY|TOKEN|SECRET|PASSWORD)=' .env*`。
- AWS のプロファイル名（`grep '^\[' ~/.aws/config`）と、SSO を使っているか。SSH を使う git のリモート（`git remote -v`）。`gh` にログインしているか（`grep -E '^[^ #]' ~/.config/gh/hosts.yml` でホストが並ぶ。ファイルには本物のトークンが入っていることがあるので残りは読まず、`gh auth token` も実行しない）。

CredShim を入れる前に設定を書いて確かめるには、[お試し構成](README.md#お試し構成) と同じようにリリースのバイナリを自分のディレクトリ（`~/.cache/credshim-setup` など）に落とす。`PATH` には置かない。使うのは `docs`・`preset`・`config check` だけ。CredShim が入っていれば、入っているバイナリを使う。

### 2. まとめて1回尋ねる

見つけたことを表にまとめる。サービスごとに、提案するプリセットか手書きのルールと、その根拠（依存関係、変数名、リモート）。そのうえで、すべてを含む質問を1回だけする。

- どのサービスを CredShim の後ろに置き、どれを外すか。
- プリセットの無いサービスは、API のホストとプロジェクトが使うパス。
- 開発ユーザーの名前（自分が動いているアカウントと違う場合）。

プリセットは `openai`・`anthropic`・`gemini`・`github`（`gh` コマンド）・`github-ssh`・`aws`・`aws-sso`（`credshim preset --help`）。

### 3. 書いて確かめる

ルールを自分のファイル（`draft.toml` など）に書く。プリセットは `credshim preset <名前>` を使い、それ以外は手で書く（`credshim docs configuration#writing-rules`）。`allow_methods` と `allow_paths` は、プロジェクトが使うものに絞る。そのうえで実行する。

```sh
credshim config check draft.toml
```

挙がった問題をすべて直し、問題が無いと言われるまで繰り返す。

### 4. 人に渡す

`config check` が表示するコマンドは、それを実行したバイナリに合わせた形になる。管理者のセッション向けの形（`sudo -u $user $bin ...`）で出すのは入っているバイナリだけなので、落としたバイナリではなく、入っているバイナリの出力を渡す。

1. 開発ユーザーが管理者か、CredShim が入っていなければ、まず必要に応じて [導入の手順 1](install.md#1-開発ユーザーを管理者でなくする) と、[手順 2](install.md#2-インストールする管理者のセッション) のインストールの1行を人に渡す。`--user` には開発ユーザーを指定する。入ったと言われるまで待つ。
2. 入っているバイナリ（[変数](install.md#変数を決める) の `$bin`）で、下書きにもう一度 `config check` を実行する。
3. 次を1つのメッセージにして人に渡す。管理者のセッションで打つ下のコマンド（下書きの絶対パスを入れる。`$user` は専用ユーザー）。チェックが端末に表示する「Where it lets each real key go」の表を読み、`!!` の付いた行をすべて確かめ、そのあとで最後のコマンドを実行してほしいという依頼。自分の実行が表の後に表示した手順（`secret set`・`ssh keygen`・`aws sso login` のコマンドと、再読み込み）。表はメッセージに入れない。人が読むのは、エージェントが変えられない写しに対して自分で実行したチェックの表。

   ```sh
   draft=$(mktemp)                               # 開発ユーザーが変えられない写し
   sudo cat /home/dev/draft.toml > "$draft"
   $bin config check "$draft"
   sudo -u $user tee -a /var/lib/credshim/config.toml >/dev/null < "$draft"
   ```

そのあと、人が終えたと言うまで待つ。

### 5. 確かめる

開発ユーザーのセッションで実行する。

```sh
. /etc/credshim/env
export PATH="/Library/CredShim/bin:$PATH"    # Linux は /usr/local/libexec/credshim
credshim verify    # 開発ユーザーが本物のキーに届かず、プロキシが止めるべきものを止める
credshim doctor    # このシェルのツールがプロキシを通り、CA を信頼している
```

失敗ごとに、示された `credshim docs` のコマンドを実行する。管理者の権限が要る直し方は人に渡す。

### 6. 仕上げる

- プロジェクトにダミーのキーを渡す（[ダミーのキーをプロジェクトに渡す](install.md#ダミーのキーをプロジェクトに渡す)）。
- [エージェントへの指示に入れる文](agents.md#エージェントへの指示に入れる文) を、プロジェクトの `AGENTS.md` か `CLAUDE.md` に足す。
- `credshim doctor` がまだ見つける古い認証情報を人に伝え、失効してもらう（[既存の認証情報を入れ替える](install.md#6-既存の認証情報を入れ替える)）。
